Controls where a risk surface exists: 6.35 / 8.0 (79%); 2 criteria scored SA (surface absent).

Cynative holds no cloud credentials of its own: it checks each model-made cloud request in code against a read-only role before attaching the credentials already in your shell, asks for approval before http_request and code_execution calls by default, and stops if the audit log can't be written. The main limits: the approval prompt isn't guaranteed to show the exact call, requests inside an approved script aren't shown individually, and the read-only ceilings are the providers' audit and viewer roles, which still permit a few non-read operations. Also missing: an explicit spend ceiling, a sandbox outside the credential-holding process, pinned permission data, and binding of cloud API requests to your own accounts (exact endpoint pinning covers Kubernetes clusters and GitLab only).

## Criterion details

### C1 Identity & least privilege: 0.72 (high confidence)

Cynative uses the credentials already in your shell and never stores any. Before attaching them, it maps each model-made request to the provider's permission model and checks it in code against a read-only role (SecurityAudit for AWS, viewer for GCP, Reader for Azure, view for Kubernetes, read-only baselines for GitHub and GitLab), denying what it can't classify. For AWS assumed-role identities it also tries to get a narrowed one-hour credential, and falls back to the original credentials if that is refused. On both AWS and GCP an individual's unpinned dataset can supply the permission answer when official or derived data has none, and when that dataset can't be loaded some requests are checked against fewer required permissions. If the gate failed, your full ambient credentials would be behind it.

### C4 Code-execution isolation: 0.78 (high confidence)

### C5 Untrusted input blast radius: 0.82 (medium confidence)

Assume an attacker controls something cynative reads: a resource tag, a repository file, an API response. The read-only ceilings block most state changes before credentials are attached, and by default every top-level call that leaves the machine waits for a human keystroke.
