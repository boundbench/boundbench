Browser Use gives a model a full web browser with no approval step, no default domain restriction, and arbitrary page JavaScript, so any web page it reads can redirect it to leak data or act on the sites it is logged into. The default throwaway browser profile limits that to anonymous browsing until a developer connects a real profile, which the project's own examples do. Telemetry is on by default and sends the task, actions and visited URLs to PostHog, and three third-party browser extensions are downloaded and loaded unverified.

## Criterion details

### C1 Identity & least privilege — 0.25 (high)

By default the agent drives a brand-new browser with a throwaway temporary profile, so out of the box it holds no logged-in sessions. But nothing scopes what it can do once a developer gives it authority: the project's own example connects the agent to the user's everyday Chrome profile, after which every site the user is logged into is fully available to the model. Credentials passed through sensitive_data can be tied to domains, though that scoping does not cover every path. There is no per-request authorization layer.

### C4 Code-execution isolation — 0.53 (high)

The default agent has no shell or host Python execution; the code the model writes is JavaScript run inside web pages through the evaluate action. That JavaScript runs in Chromium's renderer sandbox, which the library enables by default outside Docker. The sandbox blocks access to the host but not to the network or to the page's logged-in session, so model-written code can still read and send anything visible to that site. Inside Docker (or with chromium_sandbox=False) the library launches Chromium with --no-sandbox and site isolation disabled, silently.

- **S L2:** Model JS runs in Chromium's renderer sandbox, an OS-level sandbox, but the sandboxed code retains full network egress and the page origin's cookies. — [browser_use/tools/service.py:1837-1849](https://github.com/browser-use/browser-use/blob/7be96ed8bafa8dfe1eef228b59cf5c884b8b2431/browser_use/tools/service.py#L1837-L1849); [browser_use/browser/profile.py:447-448](https://github.com/browser-use/browser-use/blob/7be96ed8bafa8dfe1eef228b59cf5c884b8b2431/browser_use/browser/profile.py#L447-L448) (verified)

- **C L3:** The only model-reachable execution path in the default Agent is page JavaScript, all of which runs in the renderer; the operator escape hatch is the documented chromium_sandbox flag. — [browser_use/tools/service.py:1837-1849](https://github.com/browser-use/browser-use/blob/7be96ed8bafa8dfe1eef228b59cf5c884b8b2431/browser_use/tools/service.py#L1837-L1849); [browser_use/browser/profile.py:447-448](https://github.com/browser-use/browser-use/blob/7be96ed8bafa8dfe1eef228b59cf5c884b8b2431/browser_use/browser/profile.py#L447-L448); searched `rg -n -S 'subprocess|create_subprocess|os\.system' --glob '!**/tests/**'` in `browser_use/agent browser_use/tools browser_use/dom browser_use/filesystem` → 0 hits (no host process execution reachable from the default agent's tools) (verified)

### C5 Untrusted input blast radius — 0.25 (high)

Every step, the full content of whatever page the agent is on is fed to the model, wrapped only in a browser_state tag that nothing acts on. A hostile page can therefore steer the agent, and nothing in code limits what a hijacked agent does next: it can navigate to an attacker URL carrying data, run JavaScript, fill and submit forms, and use any logged-in session, all without a human. Password field values are kept out of the DOM snapshot, which is a useful but narrow mitigation. This is the dominant risk for a browser agent.

### C6 Memory, context & configuration integrity — 0.40 (high)

The agent keeps no long-term memory: its scratch files live in a per-run temporary directory that is wiped on start, and the default browser profile is a fresh temporary one, so poisoned content does not carry over into later runs. The one weak spot is configuration: importing the library silently loads a .env file found by walking up from the installed package, and environment variables there can switch off the Chromium sandbox (IN_DOCKER), redirect the Browser Use API endpoints, or change telemetry. The agent cannot write that file itself.
