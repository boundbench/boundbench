HolmesGPT's shell gate is better than most: commands are parsed, only a read-only allowlist runs without approval, and anything else waits for the user. But the CLI runs with the user's full kubeconfig and cloud credentials on the host with no sandbox, and its auto-allowed commands can read Kubernetes secrets, raw kubeconfig credentials and local credential files while the default web-fetch tool can reach any public host. The dominant risk is unattended credential exfiltration after prompt injection through logs, events or web pages; destructive changes still need a human, but the approval screen truncates long commands.

### C1 Identity & least privilege — 0.00 (high)

The CLI acts with whatever authority the person running it already has: their current kubeconfig context, cloud CLI logins and every environment variable, all inherited in full by each shell command the agent runs. Nothing narrows that authority or checks requests against a least-privilege policy; the README's 'read-only access' is a property of the shipped tool list and the Helm chart's RBAC, not of the CLI's credentials. Because auto-allowed commands can print kubeconfig credentials, Kubernetes secrets and local credential files, and the default web-fetch tool can send data to any public host, a hijacked session can hand those long-lived credentials to an attacker without any approval.

### C2 Approval gates — 0.45 (high)

Shell commands are checked by a parser-based gate that is on by default: commands outside a built-in read-only allowlist, compound statements and anything it cannot parse wait for the user's approval in the interactive CLI, and non-interactive runs deny them. The approval screen, however, shows the command cut off at 200 characters, so the tail of a long command can be hidden from the approver, and 'always approve' rules persist indefinitely. Only the bash tool has this gate; MCP servers and custom YAML toolsets run their tools without approval unless the operator lists them in approval_required_tools. Nothing offers undo or dry-run once a destructive command is approved.

### C5 Untrusted input blast radius — 0.30 (high)
