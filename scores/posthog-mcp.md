PostHog MCP gives an AI client the user's full PostHog authority across every organization and project: around 1,060 tools, about half of them writes, all behind one 'exec' tool that tells the host it is not destructive. Per-tool scopes, typed schemas and an opt-in read-only mode are real controls, but by default a session that reads visitor-supplied event data can also delete persons, change production feature flags and send data out through Hog functions or alerts, with no server-side human step. Model-written skills and scout notes also persist and steer other members' agents. Connect with readonly=true or a narrow features list unless writes are needed.

## Criterion details

### C1 Identity & least privilege — 0.25 (high)

The server has no identity of its own: it takes the bearer token the MCP client sends (a long-lived personal API key or a PostHog OAuth token) and attaches it to every PostHog API call, so it acts with the user's full PostHog authority. Each tool declares the OAuth scopes it needs, and the server hides tools the token lacks scopes for, but the OAuth metadata advertises every read and write scope any tool uses, and read and write share one credential. Nothing pins the session to one organization or project by default; the model can switch to any organization or project the user belongs to. A hijacked session therefore holds write access across the user's PostHog account, including feature flags that change production app behaviour.

- **S L2:** Every call carries the client's own PostHog token; per-tool required_scopes narrow the visible tool set to what the token allows, but read and write tools share that one credential. — [services/mcp/src/api/client.ts:253-256](https://github.com/PostHog/posthog/blob/282f536aa98f6de6f03d92ec719ba2e25cab0239/services/mcp/src/api/client.ts#L253-L256); [services/mcp/src/index.ts:213-215](https://github.com/PostHog/posthog/blob/282f536aa98f6de6f03d92ec719ba2e25cab0239/services/mcp/src/index.ts#L213-L215); [services/mcp/src/hono/request-state-resolver.ts:231](https://github.com/PostHog/posthog/blob/282f536aa98f6de6f03d92ec719ba2e25cab0239/services/mcp/src/hono/request-state-resolver.ts#L231) (verified)

### C2 Approval gates — 0.17 (high)

The host decides what needs approval, so what matters is the risk signal the server gives it. In the default mode for nearly every client the server exposes one 'exec' tool that runs all of its roughly 1,060 tools, reads and writes alike, and declares that tool non-destructive on purpose so hosts do not prompt on each call. Individual tools carry accurate read-only flags and a destructive flag on about 130 of them, but in the default mode the host never sees those. About 14 security-sensitive actions use a two-step prepare/execute flow, but the model itself supplies the word 'confirm', which the code documents. Persons deletion, flag rollouts, Hog function publishing and alert delivery reach the API without any server-side step.

- **S L0:** In the default CLI mode one exec tool mixes every read and write tool and advertises destructiveHint false and readOnlyHint false, so the host gets no per-action risk signal. — [services/mcp/src/hono/request-state-resolver.ts:78-79](https://github.com/PostHog/posthog/blob/282f536aa98f6de6f03d92ec719ba2e25cab0239/services/mcp/src/hono/request-state-resolver.ts#L78-L79); [services/mcp/src/tools/exec.ts:45-54](https://github.com/PostHog/posthog/blob/282f536aa98f6de6f03d92ec719ba2e25cab0239/services/mcp/src/tools/exec.ts#L45-L54) (verified)

### C3 Tool & action scoping — 0.38 (high)

Almost every tool is a narrow, typed PostHog API operation with a strict schema, path IDs are URL-encoded, and calls to tools outside the session's filtered catalog are refused. The broadest tools pass model-written content straight through, though: execute-sql runs arbitrary HogQL and can send raw SQL verbatim to a connected warehouse, Hog functions take arbitrary source code, and a connection 'escape hatch' reaches arbitrary API paths in a connected project. By default every tool group is on, including writes, across every project the token reaches; feature, tool and read-only filters exist but are opt-in.

### C5 Untrusted input blast radius — 0.25 (high)

Much of what this server returns was written by people other than the user: event and person properties sent from public websites, session data, error messages, survey answers, support tickets, LLM traces, indexed web pages and results from connected third-party MCP servers. About 50 tool responses are wrapped in a tag that tells the model the content is data, not instructions; most data-bearing tools and all third-party results are not. In the same default session the model can read customer data and send it out through Hog function destinations or Slack and email alerts, and can delete persons or change production flags, with no server-side human step. Read-only mode would remove the state-change leg but is off by default.
