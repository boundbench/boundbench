An Activepieces agent step runs unattended: every tool the author attaches executes without human approval, using the author's broadly scoped app accounts. If the content it processes (an email, a webhook payload, a web page) carries injected instructions, the agent can leak data through its built-in web fetch and send, post or write on the author's behalf. The tool layer is better than average, with author-pinned fields, credentials kept away from the model and an address-filtered fetch, but there is no way to stop a running step. In the shipped execution mode, pieces and code run in the worker container that holds the key to every stored credential.

### C1 Identity & least privilege: 0.23 (high confidence)

An agent step acts through the connections (stored app accounts) that the flow author attaches to each tool, and the shipped integrations request broad OAuth scopes, for example Gmail send, compose and modify, and wide Slack user scopes. The server keeps an unattended agent run inside its own project: it accepts runs only from a running flow, rejects chat-only and cross-project tools for unattended runs, and refuses to switch projects. Nothing narrows authority per request or per end user: whoever triggers the flow (a webhook caller, an email sender, a chat visitor) gets the author's accounts. A hijacked agent therefore holds full-account access to every connected service.

### C3 Tool & action scoping: 0.50 (high confidence)
